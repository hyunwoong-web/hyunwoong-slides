🗺️ 실습반 커리큘럼

🎯 3강의 역할

  • 1·2강에서 액셀 밟는 법을 배웠습니다 — 환경을 만들고, 도구를 만들었죠.
  • 4강부터는 실전 과제에 들어갑니다. 실제 회사 자료를 다루게 됩니다.
  • 그 전에 오늘 — 브레이크·핸들·후진 기어를 먼저 익힙니다.
오늘의 성공 = 넣기 전에 판단하고, 중간에 멈춰 확인하고, 틀리면 되돌릴 줄 아는 것
● 실습 3강 — 하네스란
Why "Harness"

AI = 고출력 엔진 · 하네스 = 사람이 잡는 고삐

🐎 엔진(AI)의 성질

  • 빠르고 강합니다 — 몇 시간 걸릴 일을 몇 분에.
  • 그런데 방향 감각이 없습니다 — 시킨 대로, 시킨 방향으로만 달립니다.
  • 모르는 것도 "모른다" 대신 그럴듯하게 지어냅니다.
  • 입력한 내용이 어디로 가는지 스스로 가려주지 않습니다.

🧑‍✈️ 하네스(사람)의 역할 — 오늘 배우는 4가지

🔒 경계무엇을 태울지 — AX 거버넌스 · 자료 등급 · 마스킹
🛑 체크포인트언제 멈춰 볼지 — 계획 먼저, 단계별 정지
🕵️ 검증결과가 사실인지 — 스팟체크·출처 대조·교차검증
🧭 조향·복원틀렸으면 — 중단(ESC)·말로 수정·되돌리기
이걸 통틀어 Human-in-the-loop — 루프(계획→실행→확인) 안에 항상 사람이 있는 운용 방식입니다.

딥시크 — 내가 쓴 프롬프트가 통째로 해외 4개사에 넘어갔다

  • 학습 거부(옵트아웃) 기능 없음, 한국어 처리방침 없음.
  • 결과: 시정 권고(이전 데이터 파기 등) + 국내 신규 다운로드 중단 사태.

💡 우리에게 주는 교훈

  • 프롬프트에 쓴 내용 자체가 '전송되는 데이터'입니다.

Our Rules · AX Governance

우리 회사 기준 — AX 거버넌스 공통 3원칙

전 구성원이 AI·자동화 자산을 회사 공용 리소스로 일관되게 다루기 위한 운영 규칙입니다.

🏢
귀속Ownership
개인이 아니라 회사가 소유합니다. 개인이 만든 프로젝트·계정·키가 아니라 회사 공용 리소스를 사용합니다.

담당자 퇴사·개인 계정 정지·원본 유실로 실무가 멈추는 것을 막기 위해 — 만든 자동화는 사내 현황 대장에 등록합니다.
🏷️
구분 · 담당Accountability
계정·키·워크플로·코드는 팀/제품 단위로 분리해 권한과 책임을 명확히 합니다.

키·폴더·계정에는 담당자/팀/제품/날짜가 드러나는 명명 규칙 — "제목 없는 프로젝트"는 아무도 못 찾습니다.
🔑
비밀 유지Secrets
민감정보는 업로드·공유 금지. 인증 세션, 서비스 계정 키, API Key 원문은 저장소·문서에 올리지 않습니다.

당연히 AI 프롬프트에도 — 키·비밀번호를 넣는 순간 유출입니다.
● 실습 3강 — AX 거버넌스 · 금지와 대안
Our Rules · Do & Don't

거버넌스 금지사항 — 전부 "대신 이렇게"가 있습니다

금지대안
고객 개인정보(이름·전화번호 등)를 외부 AI에 입력익명화(마스킹)하거나 승인된 AI 환경 사용
API Key·비밀번호 등 인증 정보를 AI에 입력대안 없음 — 절대 금지
회사 데이터를 개인 AI 계정에서 처리회사에서 제공하는 AI 계정 사용
출처 불분명한 AI 서비스·브라우저 확장 사용승인된 AI 서비스만 — 필요 시 검토 요청
어드민에서 AI에게 동작 권한 부여기획·개발팀에 공식 기능으로 개발 요청
AI 자동화가 승인 없이 고객 직접 발송·데이터 수정반드시 사람이 검토 후 사용
AI Agent에 필요 이상 권한(MCP·Drive·Slack·GitHub) 부여최소 권한 원칙(Least Privilege)
당사 대상 크롤링 / 외부 크롤링 시 robots.txt·저작권 무시사내 데이터는 관련 팀에 요청 · 외부는 공식 API 우선
승인 없이 챗봇·OAuth 앱 배포 / 업무 서비스 개인 계정 가입회사 이메일·공용 계정 사용 + 관리자 지정
거버넌스는 고정불변이 아닙니다 — 정기적으로 재검토됩니다. 오늘 강조 표시(파란 줄) 2개가 이번 강의의 핵심 구간입니다.

  • 계약서 원본 · 신분증 사본 · 계좌·결제정보
  • 미공개 전략·투자·인사 자료

Part 2 · Hallucination

AI는 "모른다"고 말하는 대신 — 그럴듯하게 지어냅니다

🧠 왜 그런가 — 원리 30초

  • AI는 "다음에 올 말"을 확률로 예측하는 기계입니다.
  • 사실을 '알고' 답하는 게 아니라 — 가장 자연스러운 문장을 만듭니다.
  • 그래서 모르는 질문일수록, 형식이 완벽한 가짜가 나옵니다.
  • 이것을 환각(Hallucination)이라 부릅니다.

🎯 오늘 기억할 한 문장

그럴듯할수록 위험하다.
판례 번호, 논문 제목, 매물 편의시설 — 형식이 완벽한 것부터 의심합니다.
  • 환각은 버그가 아니라 성질 — 완전히 없앨 수 없습니다.
  • 그래서 대책은 "좋은 AI 고르기"가 아니라 — 검증 절차입니다.

Case 4 · 되물음의 실패

뉴욕 변호사 — ChatGPT가 지어낸 가짜 판례 6건을 법원에 제출

📋 Mata v. Avianca (2023.6, 뉴욕 연방법원)

  • 변호사가 ChatGPT로 준비서면 작성 — 존재하지 않는 판례 6건 인용.
  • 판례번호·법원명·판시사항까지 형식은 완벽했음.
  • 법원이 추궁하자 — ChatGPT에 "이 판례 진짜야?"라고 되물음.
  • "LexisNexis에서 찾을 수 있다"는 답을 믿고 버팀 → 파국.
제재: 벌금 $5,000 + 공개 망신
가짜 판결문의 '저자'로 지목된 판사 전원에게 사과 서한 발송 명령

💡 핵심 교훈 — 검증의 정의

AI에게 "확실해?"라고 되묻는 건 검증이 아닙니다.
AI는 자기 환각을 자신 있게 재보증합니다.
  • 검증 = AI 바깥의 원본(문서·DB·실물)과 대조하는 것.
  • 이 원칙이 오늘 후반부(검증 파트)의 뼈대입니다.
출처
Mata v. Avianca, Inc. (S.D.N.Y. 2023) · Wikipedia · ABA Journal

Case 5 · AI의 말 = 회사의 말

에어캐나다 — 챗봇이 환불 규정을 잘못 안내, 회사가 물어줬다

📋 무슨 일이 있었나 (2024.2 판결)

  • 고객이 챗봇에 유족 할인 환불을 문의 — 챗봇: "구매 후 90일 내 신청 가능".
  • 실제 정책: 사후 소급 적용 불가 → 회사가 환불 거부.
  • 회사 항변: "챗봇의 말은 구속력이 없다" → 기각.
  • 재판소: "챗봇도 웹사이트의 일부 — 정보 정확성 책임은 회사에 있다" · CA$812 배상 명령.

💡 우리에게 주는 교훈

  • 고객 접점에 AI를 놓는 순간, 그 답변은 회사의 공식 발언.
  • 임차인 응대에 AI를 붙인다면 — 환불·위약금 규정이 가장 위험한 구간.
  • 우리 거버넌스가 "AI 자동화의 고객 직접 발송·데이터 수정은 반드시 사람 검토 후"를 못박은 이유가 이 판례입니다.
내부 업무도 동일 — AI가 써준 규정 안내·고객 발송 문구는 원문 규정과 대조 후 발송.
출처
Moffatt v. Air Canada (BC CRT, 2024.2) · The Guardian 2024.2.16

Case 6 · 전문가도 당한다

딜로이트 — AI로 쓴 정부 보고서, 가짜 인용 때문에 환불

📋 무슨 일이 있었나 (2025)

  • 호주 정부 발주 44만 호주달러 컨설팅 보고서 — GPT-4o 활용해 작성.
  • 외부 교수가 발견: 존재하지 않는 논문 인용 다수 + 법원 판결문 가짜 인용구.
  • 결과: 약 9.7만 호주달러 환불 + 수정본 재발행 + 글로벌 신뢰도 타격.
주목할 점
글로벌 최상위 컨설팅펌 — 검수 체계가 있는 조직도 검수를 건너뛰면 당합니다.

💡 우리에게 주는 교훈

  • AI 산출물의 최종 책임은 제출자 — "AI가 쓴 거라서"는 면책이 안 됩니다.
  • 보고서·리포트의 인용·수치·고유명사는 반드시 원문 대조.
  • 우리 광고 성과 리포트·시장 조사도 동일한 규칙.

호주 고용노동관계부(DEWR) 발표 · PCMag · CFO Dive 2025.10

🎯 방법 — 10분이면 됩니다

  • AI가 만든 표·리스트에서 무작위 3개를 고릅니다.
  • 각각을 원본(대시보드·엑셀·원문서)과 대조합니다.
  • 3개 모두 맞으면 → 나머지도 신뢰 가능성 높음.

👥 교차검증 — 다른 세션에 검토시키기

> report.md를 읽고 사실 오류·근거 없는
  주장·계산 실수를 찾아줘. 칭찬은 필요 없어.

🚨 중단해야 할 신호들

  • 시킨 적 없는 파일 삭제·덮어쓰기를 하려 함

  • 내가 이해 못 하는 방향으로 진행 중 — 이해 못 하면 일단 세움

파일을 망쳤다면 복원 — 3번 반복되면 사람이 개입

↩️ 파일 복원 — 고치기보다 되돌리기

  • 큰 작업 전 사본 폴더부터 — 1강의 "폴더 = 업무 하나" 구조라 복사 한 번이면 됩니다.
  • 원본 데이터는 읽기 전용으로 두고, AI에게는 "원본 수정 금지, 결과는 새 파일로"라고 지시.
  • 심화: 개발팀처럼 git(버전 관리)을 쓰면 파일 타임머신 — 4강 과제에서 필요한 분만.
  • 망친 파일을 "고쳐줘" 하며 10분 헤매기 vs 사본에서 재시작 1분 — 대부분 후자가 빠릅니다.
원칙: 되돌릴 수단을 확보한 뒤에 큰 작업을 시작합니다. 순서가 반대면 도박.

🙋 개입 — 같은 오류 3번이면 멈춤

  • 같은 지점에서 3번 실패하면 — 4번째 시도가 아니라 다른 접근.
  • 문제를 더 작게 쪼개서 다시 시키거나,
  • 그 조각만 사람이 직접 하고 나머지를 맡기거나,
  • 실습반 채널에 물어봅니다 — 같은 곳에서 다들 넘어집니다.
무한 재시도는 하네스가 아니라 방치입니다 — 시간과 토큰만 탑니다.
