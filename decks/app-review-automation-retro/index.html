느낀 점 ① — 도구 선택이 절반이었다

n8n(블록 조립)과 Python(직접 코드) — 둘 다 만들어보고 알았습니다.

🔀 n8n — 기대와 현실

  • 기대 — 블록이니까 누구나 고치겠지 (24개까지 완성)
  • 현실 — 문제 7건 중 5건이 n8n에서
  • 제약을 우회하는 시간 > 그냥 짜는 시간

🐍 Python — 주력이 된 이유

  • AI와 함께라면 코드가 곧 문서
  • 리허설·과거 채우기 같은 운영 장치를 자유롭게
  • 결국 Python 단일 트랙으로 정리

느낀 점 ② — 8할은 만들기가 아니라 '운영 설계'

1
문제를 쪼개니 기능이 나왔다
"오래 걸린다"를 4개로 쪼개니 기능 4개가 그대로.
문제 정의 30분이 기획 회의 몇 번을 아꼈다
2
지루한 '과거 채우기'가 제일 중요했다
499건을 미리 되살리지 않았다면 첫날부터 중복 알림 폭탄.
'데이터 정리부터'는 진리였다
3
초안까지 AI, 발송은 사람
이 구조 덕에 팀이 도구를 믿고 받아들였습니다.
마지막 판단을 사람에게 = 채택의 조건
4
완성 선언보다 리허설
미발송 시험 모드가 실제 발송 사고를 막았습니다.
돌려보기 전까지는 완료가 아니다

Part 2 · Trouble Map

막혔던 곳 7군데 — 같은 길을 갈 분들을 위한 지도

#문제원인해결
1구글 시트 연결 거부주소 없는 서버 차단정식 주소 발급
2필요한 기능이 안 보임보안상 꺼져 있음그 단계만 Python으로
3애플 리뷰 0건으로 읽힘형식 자동 인식 실패글자 그대로 받아 직접 해석
4시트 기록 한도 초과150건을 한 건씩 호출한 번에 몰아서 기록
5리뷰가 건너뛰어짐반복 연결이 반대로연결 바로잡음
6알림 카드가 깨짐이모지·줄바꿈이 형식 파괴특수문자 안전 처리 — AI 출력엔 필수
7갱신할 줄을 못 찾음기준 값 누락고유 번호 명시
5건은 도구의 제약, 2건은 AI 출력과 시스템의 이음새 — 자동화는 연결 부위에서 멈춥니다.
